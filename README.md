# ChatX - 멀티플레이 숫자야구

## 1. 프로젝트 소개

Unreal Engine 5.5 기반의 **2인 턴제 멀티플레이 숫자야구 게임**임.

채팅 입력창을 통해 일반 메시지를 주고받거나 세 자리 숫자를 추측할 수 있도록 제작함. 숫자 생성과 입력 검증, 시도 횟수, 턴 진행, 승패 판정은 서버에서 처리하고, 클라이언트는 전달받은 게임 상태와 결과를 UI에 표시하는 구조로 구성함.

과제의 클래스명 규칙에 맞춰 게임 관련 C++ 클래스 접두사는 `CX` 대신 `NB`(Number Baseball)를 사용함.

### 개발 환경

| 구분 | 사용 기술 |
| --- | --- |
| 게임 엔진 | Unreal Engine 5.5 |
| 개발 언어 | C++ |
| 개발 도구 | Visual Studio 2022 |
| UI | UMG, Widget Blueprint, `UUserWidget` |
| 네트워크 | Listen Server, Server RPC, Client RPC, Replication |
| 테스트 구성 | PIE 2인 멀티플레이 |

## 2. 게임 진행 방식

1. 2명의 플레이어가 접속하면 서버에서 **1~9 사이의 서로 다른 숫자 3개**를 생성함.
2. 지정된 플레이어의 턴이 시작되며 제한 시간 **20초**가 주어짐.
3. 자기 턴에 숫자를 입력하면 서버가 형식을 검사하고 정답과 비교함.
4. 올바른 숫자 입력에는 시도 횟수 1회를 사용함. 제한 시간 내에 입력하지 못한 경우에도 기회 1회를 사용함.
5. 유효한 추측 또는 시간 초과 후 다음 플레이어에게 턴을 넘김.
6. 먼저 `3S0B`를 달성한 플레이어가 승리함. 모든 플레이어가 3회씩 사용해도 정답이 나오지 않으면 무승부로 처리함.
7. 결과 화면에 승자 또는 무승부 메시지와 **이번 라운드의 정답 숫자**를 출력함.
8. 기본 **5초 후** 새 정답을 생성하고 시도 횟수를 초기화하여 다음 라운드를 시작함.

### 숫자 판정 기준

| 결과 | 판정 기준 |
| --- | --- |
| Strike(S) | 숫자와 위치가 모두 일치함 |
| Ball(B) | 숫자는 포함되어 있으나 위치가 다름 |
| OUT | 일치하는 숫자가 없음 |

예를 들어 정답이 `386`일 때 `368`을 입력하면 `1S2B`, `123`을 입력하면 `0S1B`로 판정함.

### 입력 형식

| 입력 | 처리 방식 |
| --- | --- |
| `386` | 숫자야구 추측으로 처리함 |
| `/guess 386` | 명시적인 숫자 추측으로 처리함 |
| `안녕하세요` | 일반 채팅으로 전송함 |
| `12` | 자릿수 오류 안내, 기회 유지함 |
| `112` | 중복 숫자 오류 안내, 기회 유지함 |
| `012` | 허용 범위 오류 안내, 기회 유지함 |
| `/guess abc` | 문자 입력 오류 안내, 기회 유지함 |

정답에는 `0`을 사용하지 않음. 일반 채팅은 자신의 턴이 아니어도 입력 가능하며, 숫자 추측은 자기 턴이고 남은 시간이 있을 때만 허용함.

## 4. C++ 클래스 구성

| 클래스 | 주요 역할 |
| --- | --- |
| `ANBGameModeBase` | 정답 생성, 입력 검증, 숫자 판정, 턴/타이머, 승리·무승부, 리셋 |
| `ANBGameStateBase` | 현재 턴, 남은 시간, 라운드 진행 상태 복제 |
| `ANBPlayerState` | 플레이어 이름, 개인 시도 횟수, 턴 입력 여부 관리 |
| `ANBPlayerController` | 플레이어 입력 전달, 서버/클라이언트 RPC, 로컬 UI 생성 및 결과 표시 |
| `UNBChatInput` | 입력창의 Enter 이벤트 처리 |
| `UNBChatLogWidget` | 채팅 및 숫자 판정 메시지 목록 관리 |
| `UNBMatchStatusWidget` | 현재 턴, 제한 시간, 시도 횟수 HUD 출력 |
| `UNBRoundResultWidget` | 승패 결과와 정답 숫자를 결과 위젯에 전달 |
| `ANBPawn` | 플레이어 Pawn |

### 네트워크 구조

```text
[플레이어 입력 / WBP_ChatInput]
                |
                v
       ANBPlayerController
         Server RPC
                |
                v
     ANBGameModeBase (Server)
         |            |
      일반 채팅     숫자 추측
         |            |
         |       입력 검증 및 판정
         |       시도 횟수 / 턴 갱신
         |            |
         +------ + ---+
                |
      각 PlayerController
           Client RPC
                |
                v
     각 클라이언트의 채팅 / 결과 UI

GameMode  : 서버 전용 게임 규칙 및 정답
GameState : 턴 / 남은 시간 / 진행 상태 복제
PlayerState : 플레이어별 시도 횟수 복제
```

정답은 게임 중 서버 `GameMode`에서만 보관함. 클라이언트는 정답 자체를 받지 않고 판정 결과만 전달받음. **라운드가 끝난 이후에만** 정답 숫자를 Client RPC로 전달하여 결과 위젯에서 표시함.

일반 채팅과 숫자 입력을 동일한 입력창에서 처리하지만, 서버에서 입력 유형을 분리해 채팅이 불필요한 시도 횟수를 소모하지 않도록 구성함.

## 5. UI 설계

게임 규칙과 데이터 처리는 C++에서 담당하고, 화면 디자인이 필요한 부분은 Widget Blueprint를 사용하도록 구성함.

| UI | C++ | Widget Blueprint | 담당 내용 |
| --- | --- | --- | --- |
| 채팅 입력 | `UNBChatInput` | `WBP_ChatInput` | 입력, Enter 이벤트 |
| 턴 안내 공지 | `ANBPlayerController`의 `NotificationText` | `WBP_NotificationText` | 현재 턴 안내 문구 |
| 채팅 로그 | `UNBChatLogWidget` | `WBP_ChatLog` | 메시지 추가 / 채팅 영역의 크기·위치·배경 |
| 상태 HUD | `UNBMatchStatusWidget` | 별도 BP 없음 | 현재 턴, 타이머, 시도 횟수 |
| 승패 결과 | `UNBRoundResultWidget` | `WBP_RoundResult` | 승자·무승부·정답 숫자 표시 |

### 승패 결과 UI

초기 공지 위젯을 재사용하는 방식에서 **결과 전용 위젯**으로 분리함. 서버의 승패 판정 로직은 그대로 두고, 결과 화면의 텍스트 갱신과 표시 상태는 C++에서 관리하도록 구성함.

`WBP_RoundResult`의 부모 클래스를 `NBRoundResultWidget`으로 설정함. 세 개의 Text Block을 `BindWidget`으로 연결하여 Designer에서 크기와 배치를 조절할 수 있도록 구성함.

```text
WBP_RoundResult
└─ Canvas Panel
   └─ 결과 영역
      ├─ ResultTitleText          : 승리! / 무승부
      ├─ ResultDescriptionText    : 승자 또는 무승부 안내
      └─ SecretNumberText         : 정답 숫자
```

라운드가 종료되면 `ClientRPCShowRoundResult()`로 모든 플레이어에게 같은 결과를 표시함. 표시 중에는 기존 턴 안내 공지를 숨겨 겹침을 방지함. 새 라운드 시작 시 `ClientRPCHideRoundResult()`로 결과 UI를 숨기고 턴 안내를 복구함.

**결과 표시 예시**

```text
승리!
Player2 승리!
정답 숫자 : 386
```

```text
무승부
무승부! 모든 플레이어가 기회를 소진했습니다.
정답 숫자 : 594
```

## 6. 구현 중 수정한 문제

### 채팅 메시지 중복 출력

기존에는 모든 플레이어에게 메시지를 전달하는 반복문 안에서 판정 함수까지 실행하고 있었음. 이로 인해 인원수만큼 판정이 반복될 수 있었고, 화면 디버그 로그 방식은 PIE 다중 창에서 메시지가 겹쳐 보일 수 있었음.

- 서버에서 숫자 판정과 승패 검사를 **한 번만 실행**하도록 변경함.
- 각 플레이어의 `Client RPC`를 통해 로컬 채팅 UI로 메시지를 전달하도록 분리함.
- 채팅 입력 이벤트의 중복 바인딩을 방지하도록 처리함.
- 게임 진행 로그는 화면 디버그 메시지 대신 별도 채팅 위젯에서 표시하도록 구성함.

### 로그인 중 메모리 접근 오류

접속 직후 `PlayerState`가 유효하지 않은 상황에서 참조할 가능성을 확인함. `OnPostLogin()`에서 `PlayerState` 유효성을 검사한 후 플레이어 이름과 시도 횟수를 설정하도록 수정함.

### C++ UI 빌드 오류

UMG 위젯 생성 코드에서 `Slot` 지역 변수 이름이 상위 클래스의 멤버와 겹치는 `C4458` 오류가 발생함. 해당 변수를 `CanvasSlot`으로 변경함. 이후 `SetAnchors()`와 `SetPosition()`에 잘못된 인자 타입을 전달해 발생한 `C2664` 오류를 `FAnchors`, `FVector2D` 타입에 맞게 수정함.

### 결과 공지와 UI 겹침

승리·무승부 공지를 기존 턴 안내 UI와 분리함. 결과 표시 중에는 턴 안내 위젯을 숨기고, 라운드 초기화 시 복구하는 방식으로 중복 표시를 방지함.

## 7. 실행 및 테스트 방법

1. `ChatX.uproject`를 Unreal Engine 5.5로 실행함.
2. 필요한 경우 Visual Studio 프로젝트 파일을 재생성하고 `Development Editor | Win64` 구성으로 빌드함.
3. `Chatting` 맵을 열고 World Settings의 GameMode Override가 `BP_GameModeBase`인지 확인함.
4. `BP_GameModeBase`에서 `BP_GameStateBase`, `BP_PlayerController`, `BP_PlayerState` 연결을 확인함.
5. `BP_PlayerController`의 채팅 입력, 턴 안내, 승패 결과 위젯 클래스를 확인하고 **Chat Log Widget Class**에 `WBP_ChatLog`를 지정함.
6. PIE 설정을 **Number of Players = 2**, **Play As Listen Server**로 지정함.
7. 두 화면에서 일반 채팅, 숫자 판정, 시간 초과, 승리·무승부, 라운드 초기화를 확인함.

기본 설정값은 다음과 같음.

| 항목 | 기본값 |
| --- | --- |
| 게임 시작 인원 | 2명 |
| 플레이어별 최대 기회 | 3회 |
| 턴 제한 시간 | 20초 |
| 라운드 종료 후 재시작 | 5초 |

해당 값은 `BP_GameModeBase`의 Class Defaults에서 조정 가능함.

## 9. 실행 시 확인 항목

기능 동작을 재현할 때는 PIE에서 2인 Listen Server 환경을 사용함. 다음 순서로 점검 가능함.

1. 두 플레이어가 접속했을 때 채팅이 각 화면에 한 번만 표시되는지 확인함.
2. `12`, `112`, `012`, `/guess abc` 입력 후 기회가 유지되는지 확인함.
3. 유효한 숫자 입력 시 판정 결과와 시도 횟수가 갱신되고 턴이 넘어가는지 확인함.
4. 20초간 입력하지 않았을 때 기회 1회가 소모되고 다음 턴이 시작되는지 확인함.
5. `3S0B`로 승리했을 때 결과 위젯에 승자와 정답이 나타나는지 확인함.
6. 양쪽 플레이어가 기회를 모두 사용했을 때 무승부 결과가 나타나는지 확인함.
7. 결과 표시 후 다음 라운드에서 정답과 시도 횟수가 초기화되는지 확인함.
8. `WBP_ChatLog`의 Border 크기와 폰트를 조절했을 때 채팅 내용이 정상 배치되는지 확인함.
